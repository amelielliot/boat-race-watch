# Boat Race Watch

全国24場を5分ごとに確認し、締切約10分前のレースについて、買い候補または見送り理由を iPhone の ntfy に通知する個人用ツールです。買い候補はレース確定後に的中・ハズレ、3連単払戻、レース収支、本日累計も通知します。舟券を自動購入する機能はありません。

## 初期設定

1. iPhone に **ntfy** をインストールする。
2. 推測されにくいトピック名を作成して購読する（例ではなく、長いランダム文字列を使う）。
3. GitHub リポジトリの `Settings > Secrets and variables > Actions` に `NTFY_TOPIC` を登録する。
4. `Actions > Boat Race Watch > Run workflow` でテストする。

## 判定仕様

- 対象：全国24場、締切7〜13分前
- 仮想配分：1レース合計2,000円以内。券種が増えてもレース予算は増やさない
- 検証モード：1日の金額上限に関係なく全買い候補を仮想追跡し、結果を通知
- 安全見送り：直前情報欠損、進入不明、風速6m以上、波高10cm以上、本番結果反映済み、両券種オッズ取得失敗。1号艇1着には限定しない
- 推定：`conditional-logit-v2-3t`。過去結果から学習した1着・条件付き2着・条件付き3着の別モデルを使用
- 買い候補：3連単に限定。学習モデル80%と直前オッズ由来の人気20%で確率を補正し、推定期待値1.15以上・50倍以下の候補を的中確率順に最大3点採用。3点の合計推定確率が10%未満なら見送る
- 片方の券種のオッズが不完全なら、その券種を除外。学習モデルの読込や検証に失敗したら見送りとし、旧方式へ黙って戻さない
- 結果通知：全買い候補を仮想購入として追跡し、確定後に1度だけ通知
- 成績保存：買い候補と結果を `data/ledger.json` に永久保存し、`PERFORMANCE.md` に通算収支・回収率・的中率を自動集計

## 重要

初期状態は `SHADOW_MODE=true` です。通知には金額が表示されますが、検証中は買いません。検証モードでは1日5,000円を超えても予想と結果の記録を続けます。期間の長さだけで実運用可とは判断しません。時系列で分離した評価と、将来の同条件比較で確率精度・回収率・最大下落・連敗を確認します。現段階では実購入を推奨しません。

通知は3連単の的中率重視ポリシーへ切替済みですが、これはユーザー指定による検証運用です。条件を厳しくしたため見送りは増えます。利益や旧方式への優位性を保証しません。過去の参考成績を、締切前データでの将来成績と同一視しないでください。欠場・進入・締切・最新オッズは必ず BOAT RACE 公式画面で確認してください。20歳未満は舟券を購入できません。

## データ

- 出走表・直前情報：Boatrace Open API（非公式、約3分間隔）
- 直前3連単オッズ：BOAT RACE オフィシャルウェブサイト（締切対象レースのみ低頻度取得）
- 通知：ntfy HTTP API

## 予測ロジックの比較（研究用・通知は学習版へ切替）

- `VALIDATION.md`：過去28日を学習18日・確率補正5日・評価5日に分離した初回検証。現行スコア、コース頻度、学習版v1を同一レースで比較。
- `LIVE_COMPARISON.md`：締切前に記録できたレースで、上記3方式と人気順方式を2連単1点・仮想100円に統一して比較。現行の買い候補通知とは別の評価。
- `TRIFECTA_VALIDATION.md`：条件付き3着モデルの追加学習と3連単の参考評価。既に評価した期間の再利用であり、独立検証ではない。
- `LIVE_TRIFECTA_COMPARISON.md`：3連単でも旧スコア・コース頻度・学習版・人気順を各1点100円で比較。欠損により2連単の対象レースとは異なる場合がある。
- `data/validation/notification-model.json`：通知用の3着対応モデル。1・2着の重みはv1を固定。再学習・自動最適化はしない。
- 通知にはモデル識別子を表示し、買い候補をモデル別に記録。`PERFORMANCE.md` のモデル別成績で旧方式と区別する。
- `data/validation/model.json`：学習済み重み・補正係数・学習期間を固定。自動再学習・自動採用はしない。
- `data/validation/evaluation.json`：取得元のSHA256、欠損・除外数、分割日、最終評価の各レースの予測・結果。
- `data/validation/live.json`：締切前の観測時刻・特徴量・オッズ・予想・結果。実際の購入履歴ではない。
- 過去データには締切前オッズがないため、過去の利益・回収率は計算しない。確定後アーカイブの訂正リスクもあるため、将来の検証が必須。
